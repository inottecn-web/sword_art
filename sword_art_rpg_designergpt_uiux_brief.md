# Sword Art RPG — UI/UX-бриф для DesignerGPT

## 0. Назначение

Этот документ — готовый бриф для инструмента **DesignerGPT**. Его задача: помочь сгенерировать UI/UX-концепт, вайрфреймы, визуальное направление и набор ключевых экранов для **Sword Art RPG** на основе концепта и технической спецификации проекта.

DesignerGPT должен проектировать **не обычный чат с ИИ**, а интерфейс текстово-графической MMO-RPG, где игрок выбирает только системно разрешённые действия, а сервер рассчитывает последствия. UI должен подчёркивать приключение, социальность, строгие правила и ощущение живого общего мира.

---

# 1. Краткое описание продукта

**Sword Art RPG** — web/PWA текстово-графическая MMO-RPG о совместном прохождении башни на 100 этажей.

Игроки:

- создают персонажа;
- выбирают класс и ветку развития;
- исследуют этажи башни;
- сражаются в PvE;
- участвуют в мягком и строго ограниченном PvP;
- собирают ресурсы;
- крафтят предметы;
- торгуют;
- объединяются в группы, рейды и гильдии;
- совместно готовятся к глобальным боссам;
- открывают новые этажи для всего сервера.

Ключевой принцип интерфейса:

> **Игрок не вводит свободные команды. Игрок выбирает действия из системно разрешённых вариантов. Сервер считает результат. ИИ только красиво описывает уже рассчитанные последствия.**

---

# 2. Что нужно получить от DesignerGPT

DesignerGPT должен подготовить UI/UX-концепт для MVP и дизайн-направление для дальнейшего масштабирования.

## 2.1. Обязательные результаты

Нужно спроектировать:

1. **UX-карту основного игрового цикла** — от входа в игру до первой PvE-сцены и сбора ресурса.
2. **Информационную архитектуру** — основные разделы приложения и навигация.
3. **Вайрфреймы ключевых экранов MVP**.
4. **Визуальный стиль** — цветовая палитра, типографика, настроение, компоненты.
5. **Дизайн-систему первого уровня** — кнопки действий, карточки, панели, статусы, подсказки, теги риска.
6. **Рекомендации по адаптивности** — desktop, tablet, mobile/PWA.
7. **UX-правила для запрета свободного ввода** — как сделать выбор действий удобным, не превращая игру в чат.
8. **Принципы отображения системных результатов** — броски d6, урон, награды, репутация, риск PvP.
9. **Принципы отображения ИИ-нарратива** — текст как атмосфера, а не как источник правил.
10. **Список экранов и компонентов для передачи в разработку**.

## 2.2. Формат результата

Желательный формат ответа DesignerGPT:

- краткое UX-резюме;
- user flow диаграммы в текстовом виде;
- список экранов;
- описание layout каждого экрана;
- рекомендации по visual direction;
- component inventory;
- mobile adaptation notes;
- accessibility notes;
- microcopy examples;
- что не делать.

# 3. Целевая аудитория

## 3.1. Основные игроки

1. **MMO-игроки**, которым важны прогресс, классы, группы, рейды, экономика и глобальная история сервера.
2. **RPG-игроки**, которым важны нарратив, выбор, классы, развитие персонажа и исследование мира.
3. **Игроки в текстовые/браузерные RPG**, которым важны понятные действия, быстрые сессии и атмосферные описания.
4. **Социальные игроки**, которым интересны гильдии, торговля, помощь новичкам, караваны и серверные события.
5. **Крафтеры/экономисты**, которым важны ресурсы, рынок, производство, маршруты и долгосрочная ценность предметов.

## 3.2. UX-потребности аудитории

Игрок должен быстро понимать:

- где он находится;
- что происходит в сцене;
- какие действия доступны;
- почему часть действий недоступна;
- что опасно, а что безопасно;
- какие последствия может иметь действие;
- где системный результат, а где атмосферный текст;
- что изменилось после действия;
- как его личный прогресс связан с глобальным прогрессом башни.

# 4. Платформа и технические рамки

## 4.1. Целевая платформа

- Web-first интерфейс.
- PWA-ready.
- Desktop как основной режим для глубоких сессий.
- Mobile как режим коротких сессий: сбор ресурсов, рынок, крафт, социальные уведомления, простые сцены.

## 4.2. Технический контекст

Предполагаемый стек:

- Next.js + React + TypeScript;
- Tailwind CSS + shadcn/ui;
- realtime через WebSocket/Socket.IO или аналог;
- server-authoritative actions;
- PostgreSQL как источник истины;
- Redis для presence и realtime-состояний;
- AI Orchestrator только для нарратива.

DesignerGPT не должен предлагать интерфейс, который требует свободного ввода игрока в ИИ как основного gameplay-механизма.

---

# 5. UX-принципы проекта

## 5.1. Главные принципы

1. **Системность поверх хаоса** — игрок всегда видит конкретные доступные действия.
2. **Нарратив без обмана** — красивый текст не должен обещать то, чего не произошло в системе.
3. **Прозрачный риск** — PvP, смерть, потеря ресурсов и опасные зоны должны быть явно обозначены.
4. **Быстрое понимание сцены** — в каждом состоянии игрок должен за 3–5 секунд понять, что делать дальше.
5. **MMO-ощущение общего мира** — даже в соло-сцене игрок должен видеть признаки живого сервера: хронику, присутствие, вклад сообщества, рынок, события.
6. **Мягкое обучение через реальные системы** — первый этаж не должен выглядеть как отдельный туториал, но должен учить всем базовым механикам.
7. **Доступность и читаемость** — текст важен, поэтому контраст, размеры шрифтов и иерархия критичны.
8. **Минимум когнитивной перегрузки** — сложная MMO-система раскрывается слоями.

## 5.2. Что запрещено в UX

Нельзя проектировать:

- чат как главный gameplay-input;
- поле “напиши, что хочешь сделать”;
- скрытые системные последствия без предупреждения;
- PvP-риск без явного визуального маркера;
- награды, которые выглядят как выданные ИИ;
- интерфейс, где невозможно отличить художественное описание от механического результата;
- перегруженный MMO-HUD с десятками мелких иконок на первом экране;
- мобильный экран, требующий много мелких точных нажатий.

# 6. Визуальное направление

## 6.1. Общий тон

Сеттинг — оригинальная фэнтези-MMO о башне, без прямого копирования Sword Art Online и без обязательной trapped-in-game мрачности.

Тон:

- приключенческий;
- светлый на первом этаже;
- социальный;
- исследовательский;
- с ощущением тайны башни;
- с постепенным нарастанием драматичности на верхних этажах.

## 6.2. Первый этаж

Первый этаж: **леса, поля, городок, мягкое начало приключения**.

Ключевые образы:

- городок Рассветный Порог;
- луга и светлые поля;
- лесная опушка;
- тропа рассветника;
- травы для зелий лечения;
- небольшие караваны;
- деревянные указатели;
- гильдейские доски;
- мягкий утренний свет;
- золотисто-зелёная палитра;
- ощущение безопасного старта с видимой линией риска на спорном маршруте.

## 6.3. Палитра

Предложить палитру с ролями:

- **Primary** — глубокий лесной зелёный или сине-зелёный для основного UI;
- **Accent** — рассветное золото для важных действий и прогресса;
- **Safe** — мягкий зелёный;
- **Contested/PvP** — янтарный/оранжевый;
- **Danger** — тёмный красный;
- **Magic/AI narration** — мягкий фиолетовый/сиреневый, но не как системный цвет наград;
- **Background** — тёмный пергамент, ночной сине-серый или светлая parchment-тема;
- **Surface** — карточки с лёгким fantasy-обрамлением, но без чрезмерного скевоморфизма.

## 6.4. Стиль UI

Предпочтение: **modern fantasy dashboard**.

Это гибрид:

- читабельности современного SaaS-интерфейса;
- карточной структуры RPG;
- мягких fantasy-деталей;
- карт и иллюстраций;
- ясных MMO-статусов.

Избегать:

- слишком тяжёлого medieval UI;
- чрезмерно аниме-стиля;
- cyberpunk-интерфейса;
- перегруза декоративными рамками;
- визуальной новеллы, где единственный UI — диалоговое окно.


## 6.5. Уточнённый визуальный референс интерфейса: «Sunrise Guild Atlas»

DesignerGPT должен проектировать не чат и не визуальную новеллу, а **игровой командный стол приключенца**: экран выглядит как современная MMO-панель, наложенная на иллюстрированный атлас первого этажа. Направление выбрано по принципам установленного frontend-design skill: сильная авторская эстетика, выразительная композиция, не шаблонный SaaS и не типичный AI-gradient UI.

Ключевой образ: **рассветный экспедиционный журнал гильдии**. Игрок будто открывает живую карту башни, где рядом существуют сцена, действия, партия, хроника и строгий системный расчёт.

Обязательные визуальные решения:

- **Трёхслойная композиция:**
  1. фон-атмосфера: мягкий рассвет, поля, лесная кромка, контуры башни и едва заметная сетка атласа;
  2. игровые панели: полупрозрачные parchment/glass карточки с тонкими fantasy-углами;
  3. системный слой: строгие блоки расчётов, d6, риски, требования и подтверждения.
- **Центр экрана — не чат, а сцена:** крупный scene-art/карта-зона сверху, ниже отдельные блоки NarrativeBlock, SystemResultBlock и NextActions.
- **Правая колонка — Action Deck:** вертикальная колода `ActionCard`, где каждая карточка показывает тип действия, риск, требования, стоимость, возможный результат и состояние доступности.
- **Левая колонка — Atlas & Party:** мини-карта, текущие цели, присутствие игроков рядом, группа и ближайшие серверные события.
- **Нижняя навигация — Guild Belt:** компактный пояс разделов: Персонаж, Инвентарь, Крафт, Рынок, Хроника. На mobile он превращается в bottom tab bar.
- **PvP/Contested нельзя прятать:** спорная зона всегда подсвечивается янтарным контуром, иконкой ⚠/мечей и коротким текстом потерь до подтверждения.
- **Нарратив визуально мягче системы:** AI-текст выглядит как пергаментная заметка/летопись, а системные итоги — как жёсткая таблица фактов.

Запрещённые визуальные клише для этой версии:

- фиолетово-синий generic AI gradient как главный стиль;
- обычная чат-страница с полем ввода снизу;
- тяжёлый medieval skeuomorphism с массивными рамами;
- перегруженный аниме-HUD;
- cyberpunk/neon интерфейс;
- все карточки одинакового размера без игровой иерархии.

# 7. Информационная архитектура

## 7.1. Основные разделы

Навигация должна включать:

1. **Игра / Сцена** — текущая локация, нарратив, действия, результаты.
2. **Карта этажа** — зоны, маршруты, безопасность, доступные активности.
3. **Персонаж** — характеристики, класс, ветка, экипировка, статусы.
4. **Инвентарь** — предметы, ресурсы, экипировка, расходники.
5. **Крафт** — рецепты, материалы, мастерские.
6. **Рынок / Торговля** — ордера, цены, обмен.
7. **Социальное** — группа, рейд, гильдия, друзья, приглашения.
8. **Хроника** — события сервера, first kill, открытие этажей, личная история.
9. **Задания / Цели** — личные, групповые, фракционные, серверные.
10. **Настройки** — доступность, звук, уведомления, плотность интерфейса.

## 7.2. Главный layout desktop

Рекомендуемый layout для основного игрового экрана:

- **Верхняя панель:** логотип, этаж, зона, состояние сервера, валюта/ресурсы, уведомления, профиль.
- **Левая панель:** мини-карта этажа, список целей, группа/presence.
- **Центр:** арт/сцена, основной нарратив, системный результат последнего действия.
- **Правая панель:** доступные действия, риски, требования, cooldown, подсказки.
- **Нижняя панель:** быстрые вкладки персонажа, инвентаря, крафта, рынка, хроники.

## 7.3. Главный layout mobile

На mobile использовать нижнюю навигацию:

1. Сцена;
2. Действия;
3. Карта;
4. Персонаж;
5. Социальное.

Важные правила:

- действия должны быть крупными карточками;
- подробности действия открываются bottom sheet;
- системный результат показывается компактным блоком;
- длинный нарратив сворачивается;
- PvP-риск всегда виден до подтверждения действия.

# 8. Ключевые экраны MVP

## 8.1. Landing / вход

Цель: объяснить игру за 10–15 секунд.

Блоки:

- hero: “Покори башню вместе с сервером”;
- короткое описание: текстово-графическая MMO-RPG;
- акцент: 100 этажей, общий прогресс, классы, d6, крафт, группы;
- CTA: “Создать персонажа” / “Продолжить игру”;
- блок хроники сервера: “Открыт этаж 1”, “Подготовка к первому боссу: 17%”.

## 8.2. Создание персонажа

Нужно спроектировать выбор класса:

- Мечник;
- Страж;
- Разведчик;
- Лучник;
- Маг;
- Целитель;
- Ремесленник.

Для каждого класса показать:

- роль в группе;
- сложность;
- стиль игры;
- будущие ветки;
- вклад вне боя;
- стартовую иллюстрацию/иконку;
- предупреждение, что ветка выбирается позже или уточняется по прогрессу.

## 8.3. Главный игровой экран

Должен показывать:

- название текущей зоны;
- тип зоны: безопасная / спорная / опасная;
- арт или атмосферную сцену;
- нарративное описание;
- системное состояние;
- список доступных действий;
- требования и риски действий;
- группу/presence;
- мини-карту;
- последние события хроники.

Ключевой UX: действия не должны выглядеть как варианты диалога ИИ. Это системные кнопки/карточки с понятными последствиями.

## 8.4. Карта первого этажа

Карта должна показать:

- Рассветный Порог;
- Дорогу Пастухов;
- Светлую Опушку;
- Тропу Рассветника;
- Заросший Овраг;
- безопасные, спорные и опасные зоны;
- маршруты караванов;
- источники рассветника;
- мини-босса;
- прогресс подготовки к глобальному боссу.

Нужны фильтры:

- ресурсы;
- PvP-риск;
- квесты;
- группа;
- торговые маршруты;
- угрозы;
- события сервера.

## 8.5. PvE-сцена / бой

Экран боя должен показывать:

- участников;
- инициативу/очерёдность, если используется;
- HP/ресурсы;
- статусы;
- пул d6 и модификаторы;
- сложность действия;
- результат броска;
- доступные боевые действия;
- лог боя;
- нарративный текст как отдельный слой.

Важно: игрок должен понимать, почему действие успешно или провалилось.

## 8.6. Экран результата действия

После действия показать:

- что было выбрано;
- системный результат;
- бросок d6, если был;
- успех/провал/крит;
- полученные/потерянные ресурсы;
- изменение репутации;
- изменение состояния зоны/квеста;
- короткое атмосферное описание от ИИ;
- следующие доступные действия.

## 8.7. Инвентарь и крафт

Для MVP обязательно:

- ресурс “рассветник”;
- простое зелье лечения;
- базовые материалы;
- фильтры предметов;
- сравнение экипировки;
- отображение durability;
- понятное состояние “можно скрафтить / не хватает материалов”.

UX-правило: крафт не должен скрывать системные расходы. Перед подтверждением показать стоимость, результат и шанс/сложность, если крафт требует проверку.

## 8.8. Спорный ресурсный маршрут

Нужен отдельный UX для входа на **Тропу Рассветника**.

Перед входом показать:

- предупреждение “Спорная зона”;
- что можно потерять;
- что нельзя потерять;
- лимиты грабежа;
- защиту новичка;
- потенциальную выгоду;
- активность других игроков;
- возможность пойти безопасным, но менее выгодным маршрутом.

## 8.9. Группа / рейд

MVP-экран группы:

- участники;
- роли;
- готовность;
- текущая цель;
- общий лог действий;
- быстрые команды;
- приглашения;
- состояние подключения;
- кто лидер;
- таймер принятия решения, если используется.

## 8.10. Хроника сервера

Экран хроники должен давать ощущение общего мира:

- открытые этажи;
- подготовка к боссу;
- first kill;
- вклад гильдий;
- важные караваны;
- фракционные события;
- личные достижения игрока;
- события первого этажа.

# 9. Компоненты дизайн-системы

## 9.1. Базовые компоненты

Нужно спроектировать:

- `ActionCard` — карточка системного действия;
- `RiskBadge` — safe / contested / dangerous;
- `DiceResultPanel` — кубы, сумма, сложность, margin, исход;
- `NarrativeBlock` — атмосферное описание;
- `SystemResultBlock` — строгий результат системы;
- `ResourceChip` — ресурс/валюта;
- `ClassCard` — класс персонажа;
- `ZoneCard` — зона этажа;
- `QuestObjective` — цель;
- `PartyPanel` — группа;
- `PresenceIndicator` — игроки рядом;
- `ChronicleEntry` — запись хроники;
- `InventoryItemCard`;
- `CraftRecipeCard`;
- `TradeOrderRow`;
- `BossProgressMeter`;
- `ReputationStatusBadge`;
- `PvpWarningModal`;
- `ConfirmActionDialog`.

## 9.2. ActionCard

Карточка действия должна содержать:

- название;
- короткое описание;
- тип действия;
- требования;
- риск;
- стоимость;
- возможную награду как preview;
- сложность, если есть проверка;
- состояние доступности;
- кнопку подтверждения.

Состояния:

- available;
- disabled with reason;
- risky;
- recommended;
- party vote required;
- cooldown;
- requires item;
- contested/PvP.

## 9.3. Разделение нарратива и системы

Обязательная визуальная иерархия:

- **NarrativeBlock** — художественный текст, softer style, может быть длиннее.
- **SystemResultBlock** — факты: урон, ресурсы, статусы, репутация, прогресс.
- **DiceResultPanel** — расчёт броска.
- **NextActions** — только разрешённые действия.

Нельзя смешивать художественный текст и системные награды в одном визуальном блоке.

# 10. UX для запрета свободного ввода

## 10.1. Как заменить свободный ввод

Вместо поля ввода использовать:

- карточки действий;
- grouped action lists;
- быстрые фильтры;
- контекстные меню;
- шаблонные реплики NPC;
- confirm dialogs;
- party vote;
- “показать больше вариантов”, если действий много.

## 10.2. Как сохранить ощущение свободы

Чтобы запрет свободного ввода не ощущался как ограничение, интерфейс должен давать:

- 3–6 осмысленных действий в сцене;
- разные типы решений: бой, исследование, социальное, крафт, торговля;
- объяснение недоступных действий;
- альтернативные маршруты;
- классовые варианты действий;
- групповые варианты действий;
- фракционные варианты;
- рискованные, но выгодные варианты.

## 10.3. Microcopy

Примеры:

- “Выберите действие. Система покажет риск и последствия до подтверждения.”
- “Это спорная зона: часть ресурсов может быть потеряна при нападении.”
- “Недоступно: нужен серп или навык сбора трав.”
- “ИИ описывает сцену, но результат уже рассчитан системой.”
- “Бросок d6: сумма 18 против сложности 15 — успех.”

# 11. Accessibility и читаемость

DesignerGPT должен учесть:

- WCAG-friendly контраст;
- масштабируемый размер текста;
- режим reduced motion;
- цвет + иконка для рисков, не только цвет;
- keyboard navigation для desktop;
- крупные touch targets на mobile;
- понятные empty states;
- loading/skeleton states;
- состояние reconnect;
- режим компактного лога боя;
- настройку плотности интерфейса.

# 12. UX-сценарии для проверки дизайна

DesignerGPT должен проверить дизайн на сценариях:

## 12.1. Первый вход

1. Игрок открывает игру.
2. Понимает жанр и обещание.
3. Создаёт персонажа.
4. Выбирает класс.
5. Попадает в Рассветный Порог.
6. Видит безопасное первое действие.

## 12.2. Первый сбор рассветника

1. Игрок открывает карту.
2. Видит безопасный источник и спорную Тропу Рассветника.
3. Выбирает безопасный сбор.
4. Видит d6/результат, если проверка применяется.
5. Получает рассветник.
6. Понимает, как сделать зелье.

## 12.3. Первый вход в спорную зону

1. Игрок выбирает Тропу Рассветника.
2. Видит предупреждение PvP.
3. Понимает, что можно и нельзя потерять.
4. Подтверждает вход или выбирает безопасный маршрут.
5. Видит явный contested-state в интерфейсе.

## 12.4. Первый бой

1. Игрок встречает врага.
2. Видит доступные действия.
3. Выбирает действие.
4. Видит бросок, сложность и результат.
5. Видит системный итог отдельно от нарратива.
6. Выбирает следующее действие.

## 12.5. Групповая активность

1. Игрок вступает в группу.
2. Видит участников и роли.
3. Видит общую цель.
4. Выбирает действие.
5. Видит состояние готовности группы.
6. Получает общий результат сцены.

# 13. Что DesignerGPT не должен делать

DesignerGPT не должен:

- менять геймдизайн классов, d6-системы, экономики или PvP;
- предлагать свободный ввод как основной способ игры;
- превращать игру в визуальную новеллу без MMO-интерфейса;
- делать интерфейс, где ИИ выглядит главным арбитром правил;
- скрывать риски PvP и смерти;
- предлагать pay-to-win интерфейсные паттерны;
- игнорировать mobile/PWA;
- проектировать только красивый landing без основных игровых экранов;
- смешивать системные результаты и художественные описания;
- добавлять механику, не описанную в концепте или технической спецификации.

# 14. Пример финального промпта для DesignerGPT

```text
Ты — senior UI/UX designer и product designer для web/PWA MMO-RPG.

Спроектируй UI/UX-концепт для Sword Art RPG: текстово-графической MMO-RPG о совместном прохождении башни на 100 этажей.

Ключевой принцип: это не чат с ИИ. Игрок не вводит свободные команды. Игрок выбирает только системно разрешённые действия. Сервер рассчитывает бой, d6-проверки, экономику, PvP, смерть, репутацию и прогресс. ИИ только описывает уже рассчитанный результат в отдельном нарративном блоке.

Нужно подготовить:
1. UX-карту основного игрового цикла.
2. Информационную архитектуру.
3. Вайрфреймы ключевых экранов MVP.
4. Визуальное направление modern fantasy dashboard.
5. Набор компонентов дизайн-системы.
6. Desktop и mobile/PWA адаптацию.
7. UX-решение для запрета свободного ввода.
8. Отдельное отображение SystemResult, DiceResult и NarrativeBlock.
9. UX для первого этажа: Рассветный Порог, леса/поля, сбор рассветника, крафт зелья, безопасные зоны и спорная Тропа Рассветника с ограниченным PvP.
10. Что нельзя делать в дизайне.

Ключевые экраны:
- landing / вход;
- создание персонажа и выбор класса;
- главный игровой экран сцены;
- карта первого этажа;
- PvE-бой;
- результат действия;
- инвентарь и крафт;
- предупреждение спорной PvP-зоны;
- группа/рейд;
- хроника сервера.

Стиль: оригинальная фэнтези-MMO, светлый первый этаж, леса, поля, городок, рассвет, приключение, социальность, исследование. Не копировать Sword Art Online, не делать мрачный trapped-in-game, не делать cyberpunk.

Выведи результат структурированно: UX summary, user flows, screen-by-screen layouts, visual direction, components, responsive behavior, accessibility notes, microcopy examples and design anti-patterns.
```

# 15. Критерии качества результата DesignerGPT

Результат хорош, если:

- по нему можно начать делать Figma-макеты;
- понятен основной игровой экран;
- понятна карта первого этажа;
- понятен выбор действий без свободного ввода;
- понятен d6-result UX;
- PvP-риск невозможно пропустить;
- ИИ визуально отделён от системных правил;
- mobile-версия не является вторичной после desktop;
- виден MMO-контекст общего мира;
- дизайн можно реализовать на Next.js + Tailwind + shadcn/ui без чрезмерно дорогих кастомных решений.
